# llamaswap-exporter

Prometheus metrics for the requests [llama-swap](https://github.com/mostlygeek/llama-swap) serves: per-request
decode and prefill speed, approximate time to first token, duration, context size, speculative-draft acceptance,
HTTP status, token totals and the most recently used model. One small Python process, one dependency
(`prometheus-client`), plus a ready Grafana dashboard.

## What this adds over llama-swap's own `/metrics`

llama-swap (checked at v275) has a built-in Prometheus endpoint at `/metrics`, but it only reports the **machine**:
CPU per core, memory, swap, load, network, and per-GPU temperature, utilization, memory, fan and power. It has no
request, token or speed metrics. Those live in llama-swap's activity API (`/api/metrics/stats`,
`/api/metrics/activity`), which its web UI reads. This exporter polls that API and turns each finished request into
histograms, so you can graph and alert on things like "median decode speed at 64k+ context" or "p95 time to first
token". Scrape both: llama-swap's `/metrics` for hardware, this exporter for requests (see
[`examples/prometheus.yml`](examples/prometheus.yml)).

## Metrics

| Metric | Type | Meaning |
| --- | --- | --- |
| `llamaswap_request_decode_tps{depth}` | histogram | generation tokens/s per request (>= 16 output tokens), by context depth |
| `llamaswap_request_prefill_tps` | histogram | prompt tokens/s per request (>= 256 new prompt tokens) |
| `llamaswap_request_prefill_seconds` | histogram | new prompt tokens / prompt speed: approximate time to first token |
| `llamaswap_request_duration_seconds` | histogram | whole request duration |
| `llamaswap_request_context_tokens` | histogram | whole prompt per request (cached + new) |
| `llamaswap_request_draft_tokens_total`, `..._draft_accepted_tokens_total` | counter | speculative decoding (draft model or MTP) |
| `llamaswap_request_status_total{code}` | counter | finished requests by HTTP status |
| `llamaswap_total_requests`, `_total_input_tokens`, `_total_output_tokens`, `_total_cache_tokens` | gauge | llama-swap's running totals (gauges: they restart if its store is reset) |
| `llamaswap_last_request_{duration_ms,tokens_per_second,prompt_per_second}` | gauge | the most recent request |
| `llamaswap_active_model_info{model}` | info | model of the most recent request |
| `llamaswap_exporter_up` | gauge | 1 if the last poll worked |
| `llamaswap_exporter_missed_requests_total` | counter | requests that fell off the activity page between two polls |

Speeds and token counts come from what the backend reports (llama.cpp `llama-server` timings, or the other
backends llama-swap understands). Requests that report no speed are counted in duration/status only. The first
poll after a start sets a baseline and doesn't replay old requests.

## Run

Docker (see [`examples/docker-compose.yaml`](examples/docker-compose.yaml)):

```sh
docker build -t llamaswap-exporter .
docker run -d --name llamaswap-exporter -p 127.0.0.1:9105:9105 \
  -e LLAMASWAP_URL=http://llama-swap-host:8080 llamaswap-exporter
curl -s localhost:9105/metrics | grep llamaswap_request
```

Without Docker (Python 3.10+):

```sh
pip install -r requirements.txt
LLAMASWAP_URL=http://127.0.0.1:8080 python3 llamaswap_exporter.py
```

## Settings

| Variable | Default | Meaning |
| --- | --- | --- |
| `LLAMASWAP_URL` | `http://127.0.0.1:8080` | llama-swap base URL |
| `LLAMASWAP_API_KEY` | (none) | sent as `Authorization: Bearer ...` if llama-swap has `apiKeys` set |
| `EXPORTER_LISTEN` / `EXPORTER_PORT` | `0.0.0.0` / `9105` | where `/metrics` is served |
| `POLL_INTERVAL` | `15` | seconds between polls |
| `ACTIVITY_LIMIT` | `200` | activity records read per poll (llama-swap allows 1-999) |
| `INPUT_INCLUDES_CACHE` | `1` | llama-swap v269 and newer count the whole prompt (cache included) in `input_tokens`; set `0` for v268 and older, which counted only new prompt tokens |
| `DEPTH_BUCKETS` | `8192,32768,65536,131072` | context-size edges for the `depth` label (gives `0-8k`, `8k-32k`, ..., `128k+`) |

If `llamaswap_exporter_missed_requests_total` grows, more requests finished between two polls than one activity
page holds: raise `ACTIVITY_LIMIT` or lower `POLL_INTERVAL`.

## Grafana

Import [`grafana/llamaswap-dashboard.json`](grafana/llamaswap-dashboard.json) (Dashboards → New → Import). The
Prometheus datasource is a dashboard variable, so pick yours from the drop-down at the top. Panels: requests/min,
median decode speed, draft acceptance, decode speed by depth, prefill speed, time to first token, duration,
context size, token throughput, status codes, missed requests, last model. The JSON is generated by
`grafana/build_dashboard.py`; edit that and rerun it rather than editing the JSON by hand.

## Tests

```sh
pip install -r requirements.txt
python3 -B -m unittest discover -s tests -t . -v
```

The tests use a fake activity API. The exporter was also checked end to end against llama-swap v275
(`ghcr.io/mostlygeek/llama-swap:v275-cpu-b12464`) with a stub backend that returns llama-server style timings.
